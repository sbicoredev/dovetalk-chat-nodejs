# Edge cases and gaps found while building against the mock

A working register. Each item says what could go wrong, what we do about it, and which area of the system it belongs to.
**Decision** means a call made without asking the owner. Change any of them and it is a small edit.

## Contract gaps

| # | Gap                                                                                                      | Decision                                                                                                                                                                                                                                                                                                                                               | Area                     |
| --- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------ |
| 1 | Sign-up has no phone, and contacts are added by phone, so two real users could never find each other.    | Optional `phone` on register and `PATCH /me` (confirmed with the owner). It is unique and **unverified**, so anyone can claim a number first. Documented as a demo limitation. Phones are matched on their digits only, with no country normalisation: `+1 (555) 010-0142` equals `+1 555 010 0142`, but `(555) 010-0142` does not. | auth, contacts and chats |
| 2 | Real users with the same phone as a seeded bot, or two owners adding the same unknown number.            | Bot and ghost phones live on the owner's contact row only, never on `users.phone`, so the unique index covers real users alone. Done.                                                                                                                                                                                                       | contacts and chats       |
| 3 | Adding your own number, or the same registered user twice.                                               | Own number: 422. A number you already have (same digits, same registered user or same ghost): return the existing contact with 200, re-saved if it was unsaved. Done.                                                                                                                                                                       | contacts and chats       |
| 4 | `MeDto.email` is a required string, but guests and bots have no email.                                   | Guests get a generated address on a reserved domain. Bots have none and cannot log in.                                                                                                                                                                                                                                                                 | auth                     |
| 5 | Registering an existing email needs an error code the table lacks.                                       | New codes `EMAIL_TAKEN`, `PHONE_TAKEN` (409) and `RATE_LIMITED` (429).                                                                                                                                                                                                                                                                                 | auth                     |
| 6 | The mock does not validate status `color`, but the contract limits it to 0 to 5.                                     | Validate 0 to 5 with 422. Text over 120 characters is cut, not rejected, as the mock does.                                                                                                                                                                                                                                                             | messages                 |
| 7 | `POST /contacts` for a deleted-then-re-added person, and deleting a contact who shares a group with you. | Group membership is global, so deleting a contact cannot remove them from a group. | 38 | What deleting a contact does, when the mock removes them from groups and deletes their statuses.   | Delete un-saves the contact (`saved: false`), hides the direct chat, and keeps the block flag. Statuses are part of the messages and statuses work.                                               | contacts and chats, messages |
| 39 | `GET /contacts` has to show senders who are not in the address book.                               | It lists every contact row, including `saved: false`. | 66 | Two things happen to one chat at nearly the same moment: in what order do people hear them? Two API instances can announce the same chat at once.                                 | Announcements for one chat run in a queue (a lane) per instance, so one instance says things in the order they were committed. Two instances announcing one chat at the same instant can interleave: the web client matches messages and chats by id, so a late or repeated event is harmless, and it refetches everything after a reconnect. There is no cross-instance ordering lock, because one would put Redis in every send.                                                                                                                                                                                                                                                                                                                        | realtime           |
| 67 | An event is lost: Redis is down for a second, or a client was offline.                                                                                                            | Events are sent after the transaction commits, in the background, and a failure is logged and swallowed, so a request that succeeded never turns into an error. Nothing is stored or replayed for a client that was away. The contract already says the client refetches after a reconnect, and that is the repair. `RealtimeEvents.idle()` waits for the queue, for tests and for shutdown.                                                                                                                                                                                                                                                                                                                                                              | realtime           |
| 68 | Presence: when is somebody online, and what if an instance crashes?                                                                                                               | Redis keeps a sorted set of a person's connections (score is when each stops counting) and a set `presence:due` of the people who were announced online, so being in it is the state. Every instance sweeps once a second, and Redis hands each expired name to exactly one of them, so a crashed instance's people are announced offline once by whoever is alive. Needs one Redis (or Sentinel), not Cluster, because the script builds key names. All of it is set with `PRESENCE_*` (the lifetime must be at least twice the heartbeat). | realtime           |
| 69 | Blocking and typing, presence, and `ContactDto.online`.                                                                                                                           | If either person blocked the other, neither hears the other's typing or presence, and each sees the other as offline in the contact list and in events. A message to somebody who blocked you stays as in 19.                                                                                                                                                                                                                                                                                                                                                                                     | realtime           |
| 70 | A socket is checked once, when it connects, but access tokens last 15 minutes.                                                                                                    | The server closes the transport at the token's `exp` (not a clean disconnect, which clients take as 'do not come back'), so the client reconnects by itself and presents its current token. A token past its `exp` is refused at the handshake with `UNAUTHORIZED`, even inside the 5 s of clock drift that HTTP allows, because a socket let in would be closed at once. **socket.io does not retry a refused handshake**, so the client must, on `connect_error` with `data.code === 'UNAUTHORIZED'`, refresh its token and call `connect()` again. The web client does that, and sends the new token after a refresh (see 92).                                                                         | realtime, web app  |
| 71 | Changes with no event in the contract: deleting a status, blocking a contact (apart from presence), a contact being renamed or deleted, and profile changes (name, about, photo). | None is sent. The contract has no event for them, and adding some would change what the client has to handle. The other side sees them the next time it loads. If this matters, new events are a contract change.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | realtime           |
| 72 | Who hears typing, and can somebody type into a chat they are not in?                                                                                                              | Only the other members for whom the chat is on their list (a new direct chat reaches the other person with its first message, so typing before that is not heard) and who have a contact row for the typer. Bots own no contact rows, so a bot never hears typing; a bot's own typing reaches people through the same path. The server checks membership on every event, so typing into somebody else's chat does nothing. 'Typing' passes at most once a second per chat per connection ('stopped' always passes), the payload is checked, junk is dropped without an answer, and a connection that drops while typing says it stopped.                                                                                                       | realtime           |
| 73 | Who may open a socket, and how big can what they send be?                                                                                                                         | WebSocket only (no sticky sessions needed, and one TCP stream per connection), 16 KB per message, no compression. A browser page on an origin that is not in `CORS_ORIGINS` and not the API's own host is refused. A client that sends no `Origin` (a phone app, a load test) is let through to the token check, because auth is by token in the handshake and not by cookie, so a hostile page has nothing to ride on.                                                                                                                                                                                                                                                                                                                                   | realtime           |
| 74 | Shutting an instance down while people are connected.                                                                                                                             | On SIGTERM readiness fails first and new sockets are refused with `SHUTTING_DOWN`, so they land on another instance. Then presence is released in one call (the people only this instance held go offline after the 5 s debounce unless they reconnect elsewhere, which they do), and this instance's own sockets are closed at the transport so clients reconnect. `server.disconnectSockets()` is never used, because the adapter would broadcast it to every instance.                                                                                                                                                                                                                                                                                 | realtime           |
| 75 | Telling a big group: how many queries does one message cost?                                                                                                                      | One round of queries however large the chat is (the message, the members, every recipient's address book, in one query each), and the pure projector makes each copy. Each recipient's contacts are loaded, so a 256-member group reads about N-squared contact rows per message. Fine for the demo. `docs/scaling.md` records the measurement.                                                                                                                                                                                                                                                                                                                                                                                                | realtime, scaling  |
